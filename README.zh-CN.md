# research-campaign

[English](README.md)

一个 Claude Code 技能：让一群子 agent 一起做数学研究。

## 来由

我们之前用 Claude 开了很多子 agent，做了一个挺长的数学研究项目，目标是改进一个已知的界。事后回头看，有不少 token
花在了一开始就能避免的事情上：

1. **注定打不到目标的尝试。** 有些方法就算一切顺利，也到不了需要的数，算几行就能看出来。
2. **撞上已知的障碍。** 有些障碍我们引用的论文里早就写了。
3. **用了不适用的定理。** 借来的定理，条件在我们的情形里不成立。
4. **重复干活。** 两个 agent 在做同一件事。
5. **没发现纪录已经被刷新。** 新纪录挂在一位教授的个人主页上。
6. **该查的没查。** 有的结果被反复检查了四遍，真正出错的地方反而没人查。

## 这个技能做什么

针对上面每一条，在花 token 之前先做一次便宜的检查：

1. 开打之前先算这个方法最好能到哪，到不了目标就不发。
2. 维护一张已知障碍表，撞上的新尝试直接拦下。
3. 用别人的定理之前，先核对它的条件在我们这里成不成立。
4. 新任务先和正在跑、已经跑完的任务比一下：完全重复就合并，部分重叠就把重叠的部分砍掉。
5. 先查文献，包括个人主页、直接搜目标数字、别人公开的代码。
6. 每个结果只独立检查一次。

另外，它会守住你定的预算（agent 数、内存），把大目标拆成小问题，所有路都走不通时就停下来。最后可以写论文、做 Lean
形式化。

## 效果

在长任务上大约省 20% 的 token。我们回放了一个真实项目里 3.7 小时的记录：30 次启动里有 7 次会被拦下，全都拦得对。

## 测试中发现的问题和解决办法

| 问题 | 解决 |
|---|---|
| 两个只是部分重叠的任务被合并了 | 比较各自交付什么，只砍重叠的部分 |
| 已经有定理定论的事，还跑求解器去确认 | 有定理支撑的否决直接生效 |
| 无视别人公开的纪录构造，从零开始 | 从公开的构造或代码出发 |
| 中途发现纪录变了，不同 agent 处理不一样 | 先报告，新纪录还够得着就改打新纪录 |
| 目标定得太粗（"需要 368"） | 说清楚纪录方法里哪一部分要改进 |
| 有些结果一直没人检查 | 每个结果一登记就安排检查 |
| 半小时左右的小任务反而更费 token | 小任务走轻量模式 |
| 藏在机器学习论文正文里的纪录一直没找到 | 还没解决 |
| 用 Haiku 当检查员太不稳定 | 用 Sonnet 或更强的模型 |

## 安装和使用

把整个文件夹复制到 `~/.claude/skills/research-campaign/`，或者某个项目的 `.claude/skills/` 下。需要 Python 3.11+，Lean
和 LaTeX 可选。

然后直接跟 Claude 说，比如"开个新战役，冲 X 的纪录"，或者"继续战役"。

想改设置，就把 `config.toml` 或 `budget.toml` 复制成 `config.local.toml` 或 `budget.local.toml` 再改，每一项是干什么的文件里都有注释。
